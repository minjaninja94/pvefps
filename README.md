# IRON SECTOR — PVE FPS v3

GitHub 저장소 대상: https://github.com/minjaninja94/pvefps

이번 파일은 소스와 실행 가능한 빌드, 랭킹 서버, 21개 자체 합성 효과음을 포함합니다. GitHub 업로드나 온라인 게시는 아직 수행되지 않았습니다.

## 가장 먼저: 내 PC에서 실행

Node.js 24 이상을 설치한 뒤 압축을 풀어주세요.
Windows에서는 **START-WINDOWS.cmd**를 실행하고 브라우저에서 **http://localhost:8080**을 엽니다.
터미널에서는 다음 두 명령을 순서대로 실행합니다.

```sh
npm run build
npm start
```

일반 실행에는 추가 패키지 설치가 필요하지 않습니다. 랭킹은 `.data/ranking.sqlite`에 저장되어 다시 실행해도 남습니다. 서버를 종료하려면 실행 창에서 Ctrl+C를 누릅니다.
다른 PC와 공용 랭킹을 쓰려면 아래 서버 게시가 필요합니다. **GitHub Pages에 HTML만 올리면 일반 모드는 실행되지만 랭킹 서버는 실행되지 않습니다.**

## GitHub에 업로드

ZIP을 풀고 안의 파일과 폴더를 저장소 최상위에 넣습니다. ZIP 파일 자체를 게임 파일 대신 올리지 마세요.
기존 파일이 있으면 새 브랜치를 만들고 변경 내용을 확인한 후 반영하세요. `.data`, `node_modules`는 올리지 않습니다.
이 내보내기에는 원래 Sites의 프로젝트 정보·인증값·Git 이력을 포함하지 않았습니다.

## 온라인 공용 랭킹: Cloudflare Workers + D1

게임과 API를 한 서버에서 제공합니다. Cloudflare 계정의 로그인과 데이터베이스 생성은 본인 계정에서 실행합니다.

```sh
npx wrangler@4.92.0 login
npx wrangler@4.92.0 d1 create pvefps-ranking
```

출력된 실제 `database_id`를 다음 명령의 `YOUR_D1_DATABASE_ID` 자리에 넣습니다.

```sh
node scripts/configure-d1.mjs YOUR_D1_DATABASE_ID
npm run build
npx wrangler@4.92.0 d1 migrations apply pvefps-ranking --remote
npx wrangler@4.92.0 deploy
```

완료 후 도구가 출력한 주소로 접속합니다. 기본 Worker 게시 주소는 인터넷에 공개되므로 사용할 공개 범위를 확인하고 게시하세요.
`wrangler.json`의 `DB` 바인딩은 랭킹 저장에 필수입니다. 기존 데이터베이스를 사용하는 경우 설정의 실제 이름과 ID를 맞추세요.
공식 안내: https://developers.cloudflare.com/d1/get-started/

## 조작

| 키 | 기능 |
|---|---|
| WASD | 이동 |
| Shift + 이동 | 32m/s 질주, 총을 내림, 질주 중 사격/조준 불가 |
| Space | 점프 |
| 마우스 | 시점 이동 |
| 좌클릭 / 우클릭 | 사격 / 정밀 조준 |
| R | 현재 총 재장전 |
| 1 / 2 / 3 | HK416 / 권총 / RPG |
| F | 주먹 근접 공격 |
| G | 수류탄 투척 |
| Esc | 일시정지 |

권총은 반자동입니다. RPG와 수류탄의 시작 수량은 0이며 각각 최대 5발·4개까지 보유합니다. 주황색 보급품은 RPG 탄약, 청록색은 수류탄, 녹색은 회복 키트입니다. 근처로 이동하면 줍습니다.
RPG와 수류탄 폭발은 벽에 차단되며 너무 가까이서 터지면 플레이어도 피해를 받습니다.
모바일에는 질주·무기 교체·주먹·수류탄 버튼이 포함되어 있습니다.

## 모드와 랭킹

일반 작전은 기존 5스테이지와 3단계 난이도입니다.
랭킹 작전은 극한 고정, 10스테이지이며 5단계 WARDEN, 10단계 OMEGA가 등장합니다.
랭킹 일반 적의 탄속은 26m/s, 보스 연사 28m/s, 칼날 29m/s, 유도탄 22m/s입니다. 질주는 모두보다 빠릅니다.
정찰형은 사격하지 않고 빠르게 접근해 근접 공격합니다.

10스테이지 클리어 후 이름을 1~16자로 등록합니다. 점수 내림차순, 동점이면 클리어 시간 오름차순입니다. 시간은 랭킹 서버가 시작부터 최종 완료까지 측정하며 일시정지·화면 전환 시간도 포함합니다.
점수: 정찰형 700 / 전투형 1,500 / 중장갑형 4,000 / WARDEN 20,000 / OMEGA 40,000 / 일반 부위 파괴 100 / 보스 부위 파괴 500 / 스테이지 클리어 1,000.
서버 연결이 안 되면 랭킹 모드는 시작하지 않으며 일반 모드는 실행할 수 있습니다. 클리어 기록 동기화 실패 시 결과 화면의 재시도 버튼을 사용합니다.

## 보스의 파괴 가능 부위와 패턴

파괴 부위 7개: 왼·오른 어깨, 왼·오른 팔, 왼·오른 다리, 가슴 코어. 남은 본체 장갑에도 피해를 줄 수 있습니다.

| 패턴 | 부위 파괴 효과 |
|---|---|
| 360도 회전 휩쓸기 | 팔 2개/1개/0개에 따라 반경 9m/6m/3m |
| 곡사 유도탄 | 어깨당 4발, 총 8→4→0발 |
| 지속 광역 레이저 | 코어 파괴 시 현재 레이저 중단 및 재발동 금지 |
| 탄환 3연사 | 팔 2개/1개/0개에 따라 3→1→0발 |
| 다리 칼날 부채꼴 | 다리당 5발, 총 10→5→0발 |

모든 패턴은 사전 경고를 주며, 발사 전 부위가 파괴되면 남은 예약 공격도 해당 부위 상태를 확인합니다.

## 난이도별 드롭

| 난이도 | HP 1% 이하에서 회복 드롭 최대 확률 | 회복량 | RPG 드롭 | 수류탄 드롭 |
|---|---:|---:|---:|---:|
| 쉬움 | 99% | 50 HP | 24% | 30% |
| 중간 | 50% | 30 HP | 14% | 20% |
| 극한 / 랭킹 | 30% | 20 HP | 7% | 10% |

회복 드롭 확률은 `최대 확률 × clamp((100−현재 HP)/99,0,1)`입니다. 체력이 꽉 차면 회복 키트 드롭 확률은 0입니다. 각 보급품은 적 처치마다 독립적으로 판정합니다.

## 효과음

`dist/audio`에는 원본 합성 WAV 21개가 있습니다.
정찰형의 빠른 서보·금속음, 전투형의 구동·타격음, 중장갑과 보스의 저음·유압 질감을 구분했습니다. 개체마다 피치를 조금씩 달리합니다.
거리 감쇠, 좌우 위치, 벽 뒤 감쇠, 발걸음 동기화, 효과음 볼륨, 음소거를 제공합니다. 보스 코어가 파괴되면 레이저 소리도 중단됩니다.

검색 레퍼런스:
- How to Design Game Character Robot Sound Effects: https://www.youtube.com/watch?v=OZ9-fj7vIIA
- Sound Appreciation: Titanfall 2 Ronin Movement: https://www.youtube.com/shorts/5Z7E5yjjleM

이 환경에서 유튜브 영상은 재생할 수 없었습니다. 제목과 검색 소개를 확인했으며 실제 청취나 음원 추출·복제는 하지 않았습니다. 포함된 모든 효과음은 `scripts/generate-audio.py`로 직접 합성했습니다.

## 파일 구성

- `dist/index.html`, `style.css`, `game.js`, `audio/`: 게임 화면과 음원
- `worker/api.js`: 랭킹 API
- `dist/server/index.js`: 게임과 API를 포함한 실행 빌드
- `db/schema.ts`, `drizzle/`: 데이터베이스 스키마와 생성된 마이그레이션
- `scripts/build.mjs`: 빌드
- `scripts/serve.mjs`: 로컬 SQLite 서버
- `scripts/configure-d1.mjs`, `wrangler.json`: 온라인 게시 설정

스키마를 바꾸는 개발 작업에는 `npm ci` 후 `npm run db:generate`를 사용합니다. 이미 적용한 마이그레이션을 수정하지 말고 새 마이그레이션을 추가하세요.

## 검증과 한계

전투 로직, 부위 파괴 연동, 탄약 제한, 드롭, 벽 충돌, 10단계 랭킹 저장·중복 방지 및 생성 음원의 무음/클리핑 여부를 테스트했습니다. 실제 브라우저의 시각·조작·청취 테스트는 아직 하지 않았습니다.
서버는 단계 순서·처치 수·부위 수를 검증하고 점수를 계산하지만 전투 전체를 서버에서 시뮬레이션하지 않습니다. 클라이언트를 변조하는 플레이어에 대한 완전한 치트 방지 기능은 아닙니다.
HK416 외부 모델은 여전히 미적용이며 자체 제작 임시 모델입니다. 본 작업에서 실제 GitHub 업로드·온라인 게시를 수행하지 않았습니다.
