# simsimrpg — 공동 게이트·역할별 대형·채널 도우미 봇 3인 설계

> 작성: 2026-11-02 KST. **최신 사용자 지시가 기존 '각 유저별 몬스터 게이트' 모델보다 우선한다.**
> 혼합 레벨 채널의 '고렙 만족/저렙 동기부여'는 [LEVEL_GAP_AND_PRESTIGE.md](./LEVEL_GAP_AND_PRESTIGE.md) 최신 추가 설계를 함께 따른다.  
> 상태: 게임 기획(미구현). 사용자 확정 요청과 세부 제안/시험값은 구별한다.  
> 기준 문서: [PLAN.md](./PLAN.md) · [SOCIAL_IDLE_SYSTEM.md](./SOCIAL_IDLE_SYSTEM.md) · [CLASS_CATALOG.md](./CLASS_CATALOG.md).

## 0. 최상위 확정 사항

1. **채널당 시각적으로 단 한 개의 공동 게이트**. 몬스터 웨이브는 그 게이트에서 쏟아진다. 다수의 개인 게이트·다수 전투방·맵 전환 금지.
2. **모든 채널 유저가 공동 게이트를 바라보고 포지션(역할)별 대형으로 자동 배치**되어 방어·자동사냥·치유·시너지 연계를 수행한다. 전투·채팅·친목은 처음부터 끝까지 동일 화면.
3. **채널 기본 도우미 봇 정확히 3명은 항상 배치**한다. 봇은 서버 관리형 고정 NPC이며 유저가 수집·육성·배치·합성하는 유닛 시스템이 아니다. 봇 구성/역할은 기본 탱커 1, 치유/지원 1, 공격 1을 제안한다.
4. **플레이어 계정당 활성 캐릭터 1명만 표시·사냥**하는 규칙 불변. 봇 3명은 유저 소유 캐릭터 제한에 포함되지 않는다.
5. **32개 종족 시너지 + 192개 기초 클래스 시너지 + 상위 전직 시너지 + 채널 사람 수 중첩** 원칙 유지. 봇은 '실제 채널 이용자 수'·종족/직업 시너지 스택 및 랭킹 유저 수에 절대로 포함하지 않음.
6. 게임오버 없는 무한 웨이브, 자동 장비 장착/판매, 오프라인 활성 캐릭터 1명만의 서버 사냥 정산, 수동 공동 보스 **입장 1시간 후 가능·처치 후 1시간 쿨**, 별도 보스맵 없음 원칙 유지.
7. 이전 [SOCIAL_IDLE_SYSTEM.md](./SOCIAL_IDLE_SYSTEM.md)의 **'개인 게이트당 스폰' 및 '몬스터 owner_account_id에 따른 실제 출현'** 명세는 폐기한다. 개인별 몹 생성 ON/OFF 요구는 **공동 게이트의 개인 '참전/휴식' 또는 스폰 참여 체크**로 재해석하되 실제 몬스터는 공동 게이트에서만 출현.

## 1. 공간/화면 구도 (2D 도트 RPG)

```text
┌──────────────────────────────────────────────────────────────────┐
│ 채널 / 웨이브 / 공동 시너지 / 보스 소환 남은 시간 / 레벨 / 골드     │
├──────────────────────────────────────────────────────────────────┤
│ 후방 지원                 중열                    전방       게이트│
│  힐러·버퍼              원거리 화력           탱커·방패     ███  │
│  마법·포병              근접 딜러             돌격·격투     ░█░  │
│  NPC 힐러              NPC 원거리 딜         NPC 탱커      ███  │
│                   자동 공격 / 힐 / 기합 / 시너지 이펙트            │
│                                                ← 몬스터 웨이브     │
├──────────────────────────────────────────────────────────────────┤
│ 채널 채팅 / 캐릭터 말풍선 / 게이트 참전 체크 / 난이도 / 보스 버튼   │
└──────────────────────────────────────────────────────────────────┘
```

- **단일 공동 게이트는 시각적으로 항상 같은 위치**(오른쪽, 혹은 선택한 아트 배치에 따라 상단).
- 몬스터가 한 방향(게이트 → 유저 진형)으로 진입. 보스도 같은 게이트에서 소환돼 같은 화면에서 전투.
- 캐릭터는 대형/기본 포지션으로 **자동 정렬**. 유저의 수동 이동은 가능하되 자동사냥 중에는 선택된 위치로 복귀하는 모드 제공.
- 채팅창/장비/성장/전직은 다른 맵이 아닌 화면 내 UI로 처리. 말풍선/희귀템 알림은 혼잡한 전투를 가리지 않게 레이어·표시량 제한.
- 진형이 길어져도 소셜 화면 전체 카메라가 흔들리지 않고, 위치 수에 따라 행·열을 늘리는 **포메이션 그리드**를 사용. 캐릭터 겹침/진영 스프라이트 크기(특히 용족/랩터) 고려.

## 2. 포지션 자동 분류와 유저 선택

| 포지션 | 주 대상 클래스 | 실전 역할 | 배치 |
|---|---|---|---|
| 최전열 탱커 | 기사·방패·수호·장갑·중장갑 | 적을 버티고 보호막/도발/방어 | 게이트 가까이 |
| 전열 근접·돌격 | 검객·격투·랩터·해병 돌격 | 근거리 처치·반격·출혈 | 탱커 뒤/측면 |
| 중열 원거리 | 궁수·조총수·현대군 저격·포병 | 집중 사격·범위·관통 | 전열 뒤 |
| 후열 마법·제어 | 마법사·주술사·드론·연금술사 | 광역·상태 이상·군중 제어 | 중·후열 |
| 후열 지원·회복 | 무당·의무병·치유천사·수리봇 등 | 회복·버프·디버프·보호막 | 가장 안전한 후열 |
| 측면 기동 | 닌자·암살자·고속 수인 | 후방 침투·약점 타격 | 별도 측면 슬롯 |

- 위 분류는 **'32개 진영 192개 루트 + 분기 상위 직업' 자동 전투 데이터의 role_tag로 정의**; 특정 진영 하나를 통째로 같은 위치에 넣지 않음.
- 같은 직업도 상위 전직에 따라 위치가 달라질 수 있다. 예: 조선 검객 → 방패 반격 계열은 전열, 빠른 검귀 계열은 측면.
- 직업이 극단적으로 많으므로 모든 유저가 특정 하나의 좌표를 고르는 방식 대신 **자동 자리 배정 + 포지션 우선순위 선택**을 제공.
- 포지션 제한으로 누군가 채널에서 쫓겨나는 일은 없음. 근접 플레이어 과밀 시 여러 행/측면 분산.
- 모든 포지션은 같은 공용 게이트 몬스터를 공격·치유 대상으로 지정한다. 지형/사거리도 대형 설계에 반영.
- UI에서 실시간 사람 수, 탱커/딜러/지원 인원, 종족/클래스 중첩 패시브 내역을 확인.

## 3. 기본 도우미 봇 3명(필수 고정 NPC)

| 도우미 | 기본 스킬 | 목적 | 유저가 맡은 역할이 충분할 때 |
|---|---|---|---|
| 방벽 수호봇 | 작은 도발/보호막/적 공격 방해 | 탱커 0명 채널도 계속 사냥 | 위기 대응형 보호막으로 변경/유저 탱커보다 낮은 도발 우선 |
| 회복 지원봇 | 미약한 회복/해로운 상태 해제 | 힐러 0명 채널의 최소 생존 보장 | 실제 힐러를 대신하지 않고 유저의 회복/버프를 보조 |
| 자동 전투봇 | 기본 연속 공격/약점 표식 | 혼자 있는 힐러도 일반 몬스터 처치로 기여/보상 | 유저 딜러의 표적/마무리 보조, 피해 비중 제한 |

- **확정: 항상 3명 존재**. 역할/외형/이름/스킬 수치는 설계 제안이며 추후 조정 가능.
- 봇 자체 계정/랭킹/레벨·골드·전리품/클래스 전직 없음. 게임 시작 시 채널 생성과 함께 생성, 마지막 사람이 나가도 다음 채널 렌더 때 기본 3인 표시.
- **봇은 32종 종족 시너지, 192개 클래스 시너지, 채널 인원 시너지에 기여하지 않음.**
- 봇은 콘텐츠 난이도에 맞는 **최소한의 안전망만** 제공. 권장 시뮬레이션: 유저와 동일 레벨/스펙으로 분당 DPS/회복량 1:1 비교, 봇 피해 및 회복은 해당 채널 유저 합산의 작은 비율에 캡(예: 10~20% 상한 시험값). 최종 수치는 실제 테스트.
- 특히 **유저 힐러의 고난도 도전/공동 보스 기여가 의미 있어야 함**. NPC 힐러는 큰 광역기·치명적 상태이상에 대응하는 플레이어 힐러의 상위 스킬을 대체하지 못함.
- 힐러 1명뿐인 채널에서도 봇 탱커·공격봇과 함께 사냥 가능. 해당 유저는 힐·버프·보호막의 실질 기여 또는 기본 안전 수련으로 획득 자원/경험치 정산.
- NPC 봇이 막타를 쳐도 보상은 실질 기여한 **플레이어에게** 귀속(또는 개인 자동사냥 룰에 따라 지급). 봇 이름으로 골드/아이템을 적재하지 않는다.
- 유저가 접속 종료/모바일 종료 시에도 서버가 3명의 봇을 프레임마다 시뮬레이션하지 않음. 오프라인 1활성 캐릭터의 **정해진 기본 솔로/지원 클래스 정산률**로 보상을 계산; 봇 도움을 추산값에 이미 반영하고 이중 계산 금지.

## 4. 공동 게이트 웨이브와 휴식 체크

- 기존 '내 몬스터를 게이트로 소환' ON/OFF UI를 다음처럼 재설계:
  - **[참전 ON]**: 캐릭터는 전투 대형에 배치되어 자동 공격/치유/버프, 기여·공동 사냥 보상을 받음.
  - **[휴식/구경]**: 채팅·친목만 가능하고 개인의 실시간 전투 기여·채널 시너지 집계는 악용 방지 정책에 따름. 다만 현재 이미 합의된 '계정당 활성 1명 서버 자동사냥'에 직접 모순되지 않도록 **오프라인 상태 및 온라인 휴식 보상 방식은 테스트/유저 확정 후 정의**, 휴식 중에도 자동 사냥으로 돈이 복사되는 방식은 금지.
  - 힐러는 **[참전 ON] 상태에서 본인 몬스터 소환 없이** 자동 회복/보호막/버프만 수행할 수 있음(공동 게이트 특성상 힐러 개인 소환은 존재하지 않음).
- **공동 게이트 몬스터는 참여 인원/전투 진행/채널 안정 단계에 따라 일괄 스폰**하며, 수급량이 많은 유저가 개인 게이트를 여러 개 켜서 화면 오브젝트 수를 강제로 늘리지 못하게 함.
- 기본 웨이브: 일반몬스터 지속 출현 → 일정 수 처치 시 다음 웨이브 → 강한 정예 웨이브 → 다시 일반. 자동으로 보스는 나오지 않음.
- 참가자가 적어도 시스템 봇 3명 덕분에 최소 사냥은 가능하되, **고난도 웨이브를 봇만으로 무한 돌파하지 않도록 제한**.
- 한 채널에서 전멸하더라도 게임오버 없음. 마지막 안정 웨이브로 후퇴해 재도전. 레벨/장비/숙련/골드는 유지.
- 서로 전투력이 크게 다른 유저들이 같은 게이트 앞에 있어도 **일반·강화·정예 혼합 몬스터**를 자동 공격 우선순위로 나눠 대응. 고레벨의 압도적 광역기는 보존하고, 저레벨의 기여가 막타 독점으로 0이 되지 않게 한다. 구체적인 보상·전투 구분은 [LEVEL_GAP_AND_PRESTIGE.md](./LEVEL_GAP_AND_PRESTIGE.md).
- **채널 공동 웨이브 난이도는 1개만 존재**. 개인별 난이도를 서로 다른 실제 몬스터 무리로 만들지 않는다. 기존 개인 게이트 난이도 설계는 '개인 최고 안정 단계/보상 난이도 등급'과 **채널 전체의 상위 게이트 난이도 도전**으로 분리한다.
- **상위 난이도 도전 UI 제안**: 채널 도전 난이도 상승은 참여 유저의 과반수 동의/제안에 따라 공동 게이트를 한 단계 강화(정확한 의사결정 방식은 유저 확정 전 미정). 동의하지 않은 초보자의 보상이 훼손되지 않도록 개인 보상 등급은 개인별 기여/최고기록으로 별도 산정. 같은 화면·같은 적 집단을 유지.
- 채널 이동 시 개인 레벨/장비/스킬/숙련도 보존, 새 채널 게이트의 웨이브에 합류. 별도 맵 이동 금지.
- 서버 성능: 공용 게이트 몬스터는 채널 단위 단일 스폰 큐, 동일 웨이브 상태로 권위 서버가 동기화. 멀티 유저/봇 수에 따라 몬스터 렌더 상한, 시야 혼잡 방지, 화면 오브젝트 풀링/배치 제한.

## 5. 수동 1시간 보스 규칙 유지

- 보스는 같은 **공동 게이트**에서 등장, 전장 전환 없음.
- 채널 최초 입장 후 60분 조건, 소환 버튼은 수동, 처치 **직후부터 60분 쿨다운**.
- 같은 채널에서 중복 수동 소환은 거부. 여러 명이 동시에 클릭해도 1마리만.
- 시간 판정/보상 소유/채널 호핑 악용 방지는 [SOCIAL_IDLE_SYSTEM.md](./SOCIAL_IDLE_SYSTEM.md)의 보스 절을 따르되 **게이트는 공동 단 1개**.
- 보스에서 3명의 도우미는 최소 보조만 수행. 실제 탱커/힐러/딜러/버퍼가 모였을 때 생존/시간 단축이 확실히 차이 나야 함.
- 보스 실패에도 게임오버 없음. 보스 보상은 실제 유저 기여별 지급, 힐러 치료/버프/방어 기여 포함. 봇만 때려잡으면 고급 보상 획득 제한.

## 6. 중첩 시너지 + 역할 대형의 결합

- 사람 수·32개 진영·192개 기초 직업·상위 직업 노드 시너지는 이전 설계 그대로 존재. 봇 3명은 스택 0명.
- **대형 보너스(시험 설계)**: 서로 다른 역할이 최소 한 명씩 있는 채널에 '진형 완성' 버프 추가; 예: 탱커/딜러/지원 실제 유저 각 1명씩이면 생존/화력 +3%(시험값), 3개 역할 전부라 보상이 폭발하지 않게 상한.
- 특정 클래스의 대형 위치가 무기 사거리·기술 발동 방식에 영향을 주어 눈으로 봐도 협동이 드러나게 한다.
- 힐러가 있어도 3봇의 기본 힐에 밀리지 않도록 유저 지원 스킬에 쿨타임·범위·상위 난이도 생존의 차별화(치유/감속/상태이상 해제)를 부여.
- 실제 유저가 같은 진영/클래스로 모이면 그 패시브는 중첩되지만 한 사람의 부캐는 동시 참여하지 못한다.

## 7. 서버 데이터 변경점/검증

- **삭제/대체**: `gate_settings(character_id,spawn_enabled,...)`와 `gate_mobs(owner_account_id,...)`의 **실제 몬스터 스폰 단위**는 폐기.
- **신규 예시**:
```text
channel_gates(channel_id UNIQUE, physical_gate_id UNIQUE, wave_number,
              stable_wave, difficulty_tier, spawn_budget, spawn_epoch)
gate_spawn_events(id, channel_id, wave, monster_archetype, difficulty_tier,
                  spawned_at, defeated_at)
formation_slots(channel_id, actor_type, actor_id, role_tag, x, y,
                priority, assigned_at, UNIQUE(channel_id,actor_type,actor_id))
channel_helper_bots(channel_id, bot_slot, role_tag, ai_profile_id,
                    spawn_version, UNIQUE(channel_id,bot_slot),
                    CHECK(bot_slot IN (1,2,3)))
channel_participation(account_id, character_id, channel_id, participates,
                      changed_at, version, UNIQUE(account_id))
channel_difficulty_votes(channel_id, wave, account_id, option, created_at)
```
- 몬스터/웨이브/보스/시너지 서버 권위. 봇 전용 NPC ID로 채널 시너지 스택을 증가시키거나 아이템을 획득할 수 없도록 검증.
- 매 순간 물리 게이트 ID가 채널당 정확히 1개, 봇 슬롯 1·2·3 정확히 3개.
- 한 계정이 채널 전투/대형에서 캐릭터 2명으로 중복 등장할 수 없고, 다른 부캐는 온라인/오프라인 정산 중단.
- 1인 채널(힐러·탱커·공격 클래스 각각) + 3봇으로 일반 사냥 진행, 힐러는 보조 기여 인정.
- 10/30/50인 채널에서 진형 배치/이펙트/게이트 웨이브 몹 수의 서버·클라이언트 성능 체크.
- 봇만으로 월드 보스 고급보상 농사/무한 웨이브 진행 불가, 1시간 보스 수동 소환·처치 후 60분 쿨 재확인.
- 온라인 전투와 오프라인 개인 안정 단계 정산을 비교해 봇 지원이 이중으로 보상 계산되지 않도록 검증.

## 8. 향후 확정이 필요한 세부

- 실제 사용자 수 대비 몬스터 스폰 수/공격력/체력 공식
- 공동 도전 난이도 상향을 누가 승인하고 그 안에 초보 유저가 있으면 어떻게 할지
- 온라인 유저의 '휴식/구경' 상태와 기존 활성 캐릭터 서버 정산의 정확한 관계
- 봇 3명의 기본 전투력·회복량·AI 패턴
- 다른 클래스가 부족한 경우 대형 진형 버프를 어느 정도 제공할지
- 채널 동접/화면 렌더 상한

**기본 개발 판단: 한 화면의 게이트·역할 대형·공동 전투가 소셜의 핵심이다. 봇 3명은 최소 안전망이며 실제 유저가 모여 시너지를 만들 때 훨씬 강해지는 설계.**
