- The ten user-supplied sheets are split by faction, role and action. Action sheets use 96px cells, eight presentation frames, forty rows (8 roles × idle/move/attack/skill/death). Original sources contain different pose counts; repeated source poses fill presentation cells. Extra frame positions are playback timing, not a claim of newly painted frames.
- Real sprites take priority over procedural rendering. Dedicated Odo Bongo, beastkin cavalry, wolf cavalry, transforming mech and **human** Huanglong take priority over generic roles. Aircraft for the other factions use their supplied action art.

Row boundaries are measured individually because these are illustrated reference sheets, not uniform source atlases. Extraction cannot invent missing poses; small effects crossing neighboring source frames may need manual cleanup.

## Persistent HUD and physical economy buildings

The header, resources, navigation and live frontline map now live in one sticky command stack. Base and battlefield views share the same continuously updated map. The previous third screen opens an upgrade layer below the command stack, leaving resources/map visible and the simulation running; it is also accessible above recruitment. Closing it returns to the same underlying view. The multiplayer overview and resource bar use the same command stack.

Recruitment now includes a ninth, illustrated **resource extractor**. Each extractor occupies one ordinary production slot, gives +1 CR per 0.5 seconds after stabilization, and does not spawn fighters. There can be seven extractors per commander across all lanes. Costs remain `round(70 × 1.36^currentCount)`.

A new extractor pauses that commander's entire periodic income (including base income) and wave stipend. Stabilization lasts `4 + 2 × newCount + min(6, floor(matchSeconds / 120))` seconds: 6 seconds for the opening investment, increasing to 18 seconds for seven early buildings and at most 24 seconds late in a match. This uses the game's 24-second deployment interval: early downtime is one quarter of a wave, rising toward a full wave. With +2 CR/second per extractor, the first building's 70 CR cost and 12 CR foregone base income take approximately 41 seconds to recover, compared with the old 35 seconds. Later investments incur more foregone income and must be weighed against the remaining match time. These are rule-based initial balance values, not measured player telemetry.

No income accumulates to be paid retroactively. A new extractor cannot be stacked while stabilization is active. Demolition returns 55% of the actual original purchase price and lowers income, but cannot clear stabilization. Normal troop construction remains available during stabilization. The AI follows the same costs, occupied slots and income suspension. Multiplayer performs every check on the host and hides enemy timing information.

New validation: `node desert-strike/smoke-economy.test.cjs` covers paid slots, suspended base/bonus income and wave stipends, exact resumption, no catch-up, refunds, timing bypass rejection, cross-lane seven-building cap, no combat-unit spawning and parity of both engines. DOM/native-canvas integration covers opening/closing upgrades, HUD ownership, extractor selection/building, nine multiplayer cards and the existing 80-unit raster paths. Real-device visual testing remains unverified.

The extractor image is stored at `assets/resource-extractor.webp`. It was generated with the built-in image tool using the prompt: a solitary transparent isometric pixel-art industrial resource extraction station, olive-gray steel housing, gold/cyan core, mechanical drill boring into gold crystals; complete silhouette, no ground tile, scenery, humans or text; readable at 72px. It is used in recruitment, occupied slots and the base preview.

## Twenty-troop heroes

Once per game second, the authoritative simulation finds twenty nearby full-health ordinary units with the same owner, side, faction, role, skin and max HP. Multiplayer also separates deployment bands. Damaged, captured, broodling, ink-debuffed and existing hero units are excluded. Nineteen objects are removed, and one unit represents all twenty without kill rewards for the removed members. References to removed targets redirect to the aggregate. Exactly 20× base HP, damage, armor and healing are used; armor upgrades are preserved through the stored aggregate HP. Attack interval, speed, range and AoE radius retain the original unit's values: multiplying those would exceed twenty units' combined combat output. The model/collision radius is twice as large with a pulsing red aura and rising red motes. Supply still counts twenty, and heroes do not recursively combine. Client snapshots carry the aggregate count; clients never decide authoritative merges.

## Single portraits and isolated default uniforms (2026-10-28)

Commander HQ and all ten faction selection cards now draw exactly one portrait. Default covers no longer composite a header banner with another portrait. Moe covers no longer composite a battle sprite over the portrait; the supplied multi-portrait columns have measured per-faction source windows so only one face is shown. Brood, robot and fairy default portraits are re-extracted from their actual source portrait panels, excluding the header scenery/text. Covers preserve source aspect ratio and clear the previous frame.

Default gameplay no longer reads the damaged `*-actions.webp` reference-board atlases. Production uses 80 independent `assets/sprites/uniform-{forge,brood,astral,marine,beastkin,elf,furry,robot,octoper,fairy}-{0..7}.webp` strips. Each is 768×96, with eight 96px cells and at least eight pixels of transparent border; one unit strip loads only when that unit is requested. The existing Odo Bongo, beastkin rider, wolf rider, transformer and human Huanglong artwork is preserved, cleaned of disconnected neighboring-row fragments and repacked into the same independent strips. The special renderer delegates to those strips instead of sampling the shared special atlas again.

Image creation used the built-in image generation tool with each original faction sheet as an identity/color reference. Prompt set and exact role descriptions are recorded in `tools/uniform-generation-prompts.json`: transparent square, eight roles by eight poses, one complete right-facing isometric pixel-art unit per cell, generous transparent gutters, no UI/text/portraits or adjacent figures. Outputs are converted by `tools/extract_uniform_sprites.py SOURCES.json`. Source filenames, hashes, measured row boundaries, source crop boxes and preserved special-unit flags are recorded in `assets/sprites/uniform-manifest.json`.

Generated oversized impact/summon columns are deliberately excluded where effects bridge neighbors. The accepted complete rest/strike sprites form the attack sequence; movement uses the two complete stride poses; death uses a complete defeated pose with runtime fading. Some presentation cells repeat accepted poses rather than importing clipped bodies or a second summoned character. Padding and a shared scale per ordinary unit keep complete silhouettes and stable body size. The unused legacy reference files remain available as historical extraction inputs, but are never requested by the default combat renderer.

Validation includes real WebP dimensions (80 separate one-row strips), all default animation crop bounds, default and moe covers drawing exactly one image, preserved five special-unit routes, native-canvas/DOM rendering, visual roster checks and existing account, hero, economy and cooperative-network regressions. Cache versions are updated to `uniform7` so returning browsers request the corrected renderer and portrait assets.
